# Google 日历与 TodoTodoList 信源分工及实施计划

日期：2026-09-23。状态：已明确产品方向，本文是待实施计划，不代表新同步规则已经上线。

用户要求：有具体日历时间的事件以 Google 日历为唯一信源；想法、放弃等 TodoTodoList 专有信息以 TodoTodoList 为唯一信源。计划中不批量修改真实事项、清理冲突或写入 Google。

## 1. 以字段和对象划分归属

“放弃”是行动状态，不是另一类日历事件。已排期行动同时具有日程和执行信息，两者分别由所属系统管理，不做整条记录覆盖。

| 信息 | 权威来源 | 同步规则 |
| --- | --- | --- |
| 已关联 Google 的开始/结束时间、全天、时区、重复规则及单次例外、日历取消状态 | Google Calendar | Todo 保存已确认镜像；Google 改动更新镜像，设备缓存和 GitHub 导入不能覆盖 |
| 纯日历事件标题、说明、地点、提醒 | Google Calendar（计划采用的边界） | 镜像展示；Todo 的补充备注另存，不混入同一说明字段 |
| Todo 行动/想法自身的标题、描述、类型、想要/正在/搁置/放弃/完成、标签、附件、反馈 | TodoTodoList 服务器 | Google 同步不能改写；已关联日程也不改变这个归属 |
| 版块、全局偏好、树节点关联 | TodoTodoList 服务器 | 浏览器仅缓存与提交命令；新设备先拉服务器，不生成第二套默认配置 |
| 设备专属状态（推送订阅、离线队列、同步基线） | 对应设备/服务端专门记录 | 不作为全局 default 设置跨设备覆盖 |
| 未发布的排期意图/草案 | TodoTodoList | 与 Google 已确认时间分开；发布成功才形成权威日程 |
| 完整目标树和个人材料 | 本机目标树/关联目录 | 延续现有分工；本次不迁移、不自动改变节点状态 |

有时间字段不等于已有 Google 日程。未关联记录先标为排期草案/待发布，不能仅凭 startAt 自动绑定、上传或反向判定已经完成。截止日期、不要做的约定时间窗仍可留在 Todo；用户明确安排日历时才创建关联日程。

同一行动可对应多个日程实例，行动标题和日历标题分开保存。纯日历事件以 Google 标题展示；Todo 行动以自身标题展示并附关联日程。不得按标题或描述猜关联。

## 2. 用户操作及竞争处理

- 在 Todo 改日历时间：提交显式日历命令，携带稳定关联、读到的 Google 版本和幂等 ID；显示“待 Google 确认”。确认前保留原日历镜像，草案单独显示。
- Google 已有更新：重新读取 Google 版本，取消旧基线的自动重试。Google 版本成为当前事实，原请求保留为未应用意图；用户需要坚持改期时，从新基线提交，不强行覆盖。
- 断网：保存待发命令；联网先拉权威状态，再校验、提交。不能上传整份旧快照替代当前服务器数据。
- Google 取消/删除日程：取消对应日程、停止该日程提醒，保留 Todo 行动、放弃/完成状态、反馈及历史。纯镜像事件退出活动日历视图。
- Todo 放弃/搁置行动：保存 Todo 状态，停止后续自动排期与执行催促。既有 Google 事件不因状态变化被暗中删除；另提供明确的“取消关联日程”操作。
- Todo 完成：保存实际反馈，不删除 Google 历史日程。日程结束继续显示历史待确认，不自动完成行动。
- Todo 删除与 Google 删除分开操作；界面说明作用范围，已有通用删除接口不得隐式级联远程删除。

上述 Google 写入模式沿用“Todo 可作为编辑入口”的能力；唯一信源指已确认数据的归属，不禁止从 Todo 发起明确的 Google 编辑请求。

## 3. 当前代码中的修改点

- `src/execution/calendar.ts`：Google 镜像与 Item 执行状态分开；避免远端取消直接写 Item.deletedAt，避免日历标题覆盖 Todo 行动标题；明确全天和重复实例的标准表示。
- `src/execution/core.ts`、`src/check-ins/service.ts`：拆开行动状态、日程取消、反馈与提醒；审查不再 eligible 时的自动删除日历请求。
- `src/execution/service.ts` 的 mergeWorkspace/resolve：当前按整对象 digest 判冲突，resolve 可以整对象替换。改为归属校验加字段级命令，两个入口都不能让导入覆盖 Google 镜像。
- `src/local-db/db.ts`、`src/sync/server-workspace.ts`：服务端模式先读取服务器，初始化前不创建示例事项和第二份默认配置；首次只迁移真正的本地内容；保留离线队列、基线和在途修改保护。
- 浏览器日历写回入口、外部 Item API、日历专用 API、GitHub/JSON 导入均通过相同归属层，不能只修 worker 而留下绕行接口。
- `app/today/TodayWorkspace.tsx`：冲突展示标题、对象类型、字段差异、来源与时间；回顾区域继续优先展示。

仓库已有未提交的 calendar-api/calendar-binding 等工作。实施前逐项审阅、检查接口重叠、修复其独立检查问题，再决定复用或单独提交；不得把在途实现当成已验收能力。

## 4. 冲突规则

1. 比较业务字段，忽略 createdAt/updatedAt 等纯元数据差异；相同业务内容自动保持权威版本，记录处理依据。
2. Google 字段导入差异采用最新 Google 镜像，不再要求用户二选一；离线改期意图进入专用请求状态。
3. Todo 字段使用服务器版本与设备基线做三方合并：不同字段可合并，同一字段不同修改才要求选择。仅说“服务器权威”不能丢弃真实离线编辑。
4. 默认配置缺失字段按模式版本补齐，不把缺省值与缺失值一律视为不同；有意义的偏好差异仍需核对。
5. 冲突按实体、字段集合、基线和候选内容的规范摘要去重；不同真实候选保留，不按同名简单删除。保留各迁移请求来源。
6. 解决冲突只应用核对过的字段，并校验服务器当前版本；重复提交幂等，后来无关修改保留。
7. 删除标记、附件、反馈和用户输入不得因“看起来像示例”自动丢弃。示例 ID 只辅助定位，不能作为删除依据。

## 6. 必测场景

- 两台设备初始化同一账号，不再生成同一批默认事项/版块冲突。
- Google 改期 + 手机同时标完成：时间采用 Google，完成采用 Todo，两者均保留。
- Google 更新 + 手机离线改期：旧请求不覆盖远端，意图可追溯且不无限重试。
- Todo 放弃 + Google 同步：放弃不被恢复为正在；不会自动删除原 Google 日程。
- Google 删除 + 已有反馈：日程取消，反馈和行动保留。
- 重复事件单次改期/取消、全天排他结束日期与时区跨日，无重复绑定或偏移。
- 增量同步重建、接口超时/重试、导入旧快照、重复冲突请求均幂等，不复活删除记录。
- 现存 9 条纯时间冲突可按规则自动归并；其他真实差异保留明确候选和来源。
