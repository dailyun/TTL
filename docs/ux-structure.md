## 2. 首页

首页建议不是营销页，而是直接进入工作台。

布局：

```txt
Header: 快速新增 + 搜索

Main:
  左侧：收集箱
  中间：正在
  右侧：今日 / 接下来

Footer/Side:
  同步状态
```

首页模块：

- 收集箱：未整理的 Idea / Todo。
- 正在：active 状态事项。
- 今日：今天有时间的 Todo / Event。
- 接下来：未来 7 天事项。

设计重点：

- 首页应该帮助用户立即知道「现在有什么」「今天有什么」「有什么刚记下来还没整理」。
- 不建议第一屏做大面积统计图，早期用户更需要行动入口。

## 3. 快速新增

入口：

- 顶部输入框。
- 键盘快捷键占位。
- 每个视图的新增按钮。

最小输入：

```txt
标题
类型: Idea / Todo / Event
版块: 收集箱 / 工作 / 生活 / 自定义
状态: 想要 / 正在 / 搁置 / 放弃 / 完成
时间: 无 / 日期 / 时间段
```

默认值：

- type: Idea
- section: 收集箱
- status: 想要
- time: 无

智能规则建议：

- 如果用户选择了开始时间，默认类型可切换为 Event。
- 如果用户选择了完成状态，自动从主视图弱化展示。
- 如果用户输入内容很短，不强制填写描述。

## 5. 看板视图

列：

- 想要。
- 正在。
- 搁置。
- 放弃。
- 完成。

交互：

- 拖拽卡片改变状态。
- 点击卡片打开详情抽屉。
- 卡片菜单支持转为 Todo、安排时间、复制、删除。
- 默认可以折叠放弃和完成两列。

卡片内容：

- 标题。
- 类型图标。
- 版块色点。
- 时间。
- 标签。
- 优先级。

## 6. 日历视图

MVP 推荐先做周视图，原因是：

- 个人工作台更需要看近期安排。
- 周视图比月视图更适合安排具体时间段。
- 日视图可以后续补充。

日历项来源：

- 本地 Event。
- 带 startAt 的 Todo。
- Google Calendar 双向同步事件。

显示规则：

- 本地 Todo 用状态色或浅色条展示。
- Event 用版块色展示。
- Google Calendar 同步事件应有来源标识。
- 放弃状态默认不显示在日历中。
- 完成状态可在设置中选择是否显示。

交互：

- 点击空白时间创建 Event。
- 点击事项打开详情。
- 拖动调整时间可以先只支持本地事项。
- Google 同步事件允许编辑，但需要清楚标识同步状态和冲突状态。

## 7. 版块管理

默认版块：

- 收集箱。
- 工作。
- 生活。

自定义版块字段：

- 名称。
- 颜色。
- 排序。
- 是否归档。

交互：

- 新建版块。
- 重命名。
- 调整排序。
- 归档版块。

注意：

- 归档版块不删除历史事项。
- 收集箱不能删除。

## 8. 详情抽屉

打开方式：

- 点击列表行。
- 点击看板卡片。
- 点击日历项。

字段：

- 标题。
- 类型。
- 状态。
- 版块。
- 描述。
- 标签。
- 优先级。
- 时间。
- 来源。
- 外部链接。
- 创建时间 / 更新时间。

主要操作：

- 保存。
- 删除。
- 标记完成。
- 搁置。
- 放弃。
- 转成 Todo。
- 安排时间。

## 9. 设置页

模块：

- 数据导入导出。
- GitHub 私有库同步。
- Google Calendar 连接。
- 本地数据清理。
- 外观与显示偏好。

GitHub 远端数据源设置字段：

- GitHub owner。
- repo。
- branch。
- data path。
- last sync time。
- sync mode: manual / automatic。

Google Calendar 设置字段：

- 连接状态。
- 授权账号。
- 已选择日历。
- 同步范围。
- last sync time。

## 10. 空状态

收集箱为空：

> 没有未整理的内容。

正在为空：

> 现在没有正在推进的事项。

日历为空：

> 这段时间没有安排。

看板为空：

> 先记录一个想法或 Todo。
