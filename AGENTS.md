## Public repository privacy

- Keep tracked files limited to source, synthetic examples and reusable documentation. Use `example.com` domains and placeholder workspace paths in examples.
- Keep personal directories, host addresses, account identifiers, real schedules/feedback, device counts and deployment journals in private configuration or a private runbook outside the repository.
- Never commit live environment files, credentials, runtime state or backups. Before committing documentation copied from a live session, inspect the staged diff for personal data.
- Label synthetic examples clearly. Preserve real operating records privately before replacing public documentation; a new commit does not remove old content from Git history.
